overview: >-
  agent-middleware 是一个部署在容器内部的 Agent 聚合网关。它位于 agent-interface 前端与不同 Agent 后端服务之间，对前端暴露统一的 OpenClaw WebSocket 入口，并通过 claw / paw 两种模式适配 WebSocket 透明代理与 QwenPaw SSE API。

problem: >-
  前端平台需要连接多个 Agent 服务，但不同服务可能暴露不同协议：部分服务使用 OpenClaw WebSocket，部分服务使用 QwenPaw HTTP/SSE。若前端直接适配每种协议，会造成协议逻辑分散、连接生命周期重复实现、审批和模型等事件难以统一，也不利于在容器内维护和替换后端 Agent 服务。

solution: >-
  项目以 Fastify 5 构建统一 WebSocket 网关，通过 ModeConfig 与 AgentRegistry 管理 claw / paw 两类后端接入形态。claw 模式作为透明 WebSocket 代理，paw 模式将前端 OpenClaw WebSocket 请求转换为 QwenPaw HTTP/SSE 调用，并使用 adapter、session、heartbeat、protocol reducer、approval watcher 和 model service 等模块统一处理连接、消息流、审批、模型与资源清理。

challenges:
  - "claw 与 paw 后端协议不同，但前端需要保持同一套 OpenClaw WebSocket 协议。"
  - "SSE 是单向流，需要通过 WebSocket handler 协调前端主动请求、停止、上传与审批事件。"
  - "QwenPaw 长时间工具调用会触发默认超时，需要禁用或调整 undici 的默认 5 分钟限制。"
  - "连接、会话、pending 文件暂存等状态在容器进程内管理，水平扩展时需要会话粘滞或共享存储。"
  - "ApprovalWatcher 轮询审批消息，高并发场景需要评估上游压力。"

outcome: >-
  项目形成了一个轻量级 Agent 连接适配网关，使 agent-interface 前端无需感知后端 Agent 协议差异即可统一连接容器内部的 OpenClaw 或 QwenPaw 服务。它既可作为透明 WebSocket 代理，也可承担 SSE 协议转换、流式内容归约、安全审批推送与模型状态管理。
